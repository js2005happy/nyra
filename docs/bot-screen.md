# Bot 看屏与接管（缺口 50：live screen + 活动列表 + 接管）

Bot 电脑的“人机协作面”：先做“看”，再做“接管”。第一批只做“看”
（live screen + 活动列表，只读）；第二批做“接管”（take the wheel：
登录墙 / 2FA / 敏感步骤时交人操作，全程记审计，接管完交还给 Bot）。

## 命令

| 命令 | 作用 |
|---|---|
| `nyra screen watch <电脑 id> [--as <身份>] [--run <运行 id>] [--text <画面文字>]` | 看屏（只读）：一帧快照 |
| `nyra screen activity <电脑 id> [--as <身份>] [--run <运行 id>] [--limit N]` | 活动列表（只读）：正在做什么 + 下一步 |
| `nyra screen status <电脑 id> [--as <身份>]` | 看屏可用性：电脑状态、上次访问、最近活动、当前有没有人在接管 |
| `nyra screen takeover <电脑 id> [--as <身份>] [--reason <原因>] [--run <运行 id>] --yes` | 接管（take the wheel）：人接手，Bot 暂停；须确认 |
| `nyra screen handover <电脑 id> [--as <身份>] [--did <做了什么>] [--resume-from <从哪步继续>] [--run <运行 id>]` | 交还：把电脑还给 Bot，暂停的任务回队列从挂起点继续 |

`--as` 指定看屏/接管的人是谁，默认机主（`owner`）。

## live screen：画面从哪来

画面来自缺口 42 的电脑：

- 正在看哪个页面：电脑 profile 的上次访问 host（只记 host，不记路径与
  query，见 `recordBrowserVisit`）。
- 最近在做什么：活动账本（`~/.nyra/bot-computer-activity.jsonl`）的最新一条。
- 每一帧只是一次确定性快照：帧指纹是 SHA-256 前 12 位（电脑 id + 快照时间
  + host + 最近动作拼起来哈希，与缺口 39 的扇出同一口径），收件人只有看屏
  的人自己。**只记帧指纹与收件人，不记帧内容、不截图留存。**
- 休眠的电脑没有实时画面：`live` 为 false、帧指纹为 null，不报错——
  先 `nyra bot computer wake <电脑 id>` 再看。

看屏本身记一笔活动账本（`browser/screen.watch`：谁看的、看了哪台、哪个
host），这是审计，不是写操作。`--run` 给了运行 id 且运行真实存在时，再
镜像一条 `bot_screen_watched` 运行事件（电脑、看屏的人、帧指纹、host）。

## 活动列表：与时间线同源

不另起一套活动账本：

- **正在做什么**：活动账本最新一条（运行事件 `bot_computer_*` 镜像的源头）。
- **下一步**：关联运行的时间线阶段（缺口 21 的 `buildTimeline` +
  `stageDisplay`）：等审批 / 卡住 / 等审阅 / 进行中 / 空闲。关联运行优先
  用 `--run` 指定的，其次向后找最近一条带 `runId` 的活动（看屏本身不带
  runId，不能只看最新一条）。
- 两者都没有时，下一步明说“看不到（没有关联运行；给 `--run <运行 id>` 接
  时间线）”，**不编一个**。

## 隐私打码：确定性规则

画面文字（活动摘要，或调用方用 `--text` 传进来的视觉描述）先过确定性打码，
打码后的文本才往外给，原文不留存：

| 种类 | 规则 |
|---|---|
| `payment`（支付信息） | 卡号形状：4 组 4 位数字（可带空格/连字符）；或“卡号/银行卡/card number”字样后跟的一长串数字 |
| `password`（密码） | `<input type=password>` 框整个打掉；“密码/password/passwd”字样后跟的值打掉 |
| `verification_code`（验证码） | “验证码/verification code/OTP”字样附近的 4–8 位数字 |

打码命中时记一条 `bot_screen_redacted` 运行事件（有 runId 且运行存在时才
镜像），**只记打了哪几类，不记原文**。打码是确定性规则，不调模型——
没命中规则的敏感串仍可能漏网，别把打码当万无一失的脱敏。

## 谁能看：只对机主与信任圈成员可见

准入复用缺口 34 的 `isAdmitted`：机主永远能看；别人须是已批准、未拉黑、
且在任一信任圈里的好友。圈外直接拒绝（`nyra screen` 返回 1，stderr 明说
原因），拒绝本身不记敏感信息。

## 看懂屏幕内容：复用缺口 16，不另起一套

真画面上的 OCR / 视觉描述走缺口 16 的视觉能力（`describe_image` 同款门禁：
模型须支持看图，本地小模型优先、云端须绑定显式开，见缺口 27 的口径）。
`--text` 就是给这条路留的口子：调用方把视觉描述传进来，先打码再往外给。

## 接管（take the wheel）：人接手，Bot 暂停，交还后继续

接管是审计事件，不是悄悄接手。

**生命周期**：`takeover`（须 `--yes` 或交互确认，未确认不接管）→
接管期间 Bot 暂停 → `handover` 交还给 Bot。

- **谁能接管**：只认机主或信任圈成员（缺口 34 的 `isAdmitted`，与看屏
  同款门）；圈外直接拒绝。交还只能由接管那个人或机主做，别人不能替人交还。
- **什么时候不能接管**：电脑在休眠时没有进行中的操作可接管（先唤醒）；
  同一台电脑不能同时有两场接管（第二场直接拒绝，先等上一场交还）。
- **Bot 暂停（防双写）**：接管时，该电脑 agent 的 `working` / `queued`
  任务全部进 `paused`（复用缺口 26 的暂停/恢复口径，历史备注记“接管暂停”，
  不是分层成本上限）；新任务启动被拒（`startKanbanTask` 的守卫）、调度
  tick 直接跳过（不 claim、不进 fail 路径）。交还时，接管时暂停的任务里
  仍是 `paused` 的回 `queued`（下一轮 tick 再跑）；中途被人手动恢复过
  的不再动。电脑本身的状态机不动：`ComputerState` 只认 `active` /
  `sleeping`，接管不改电脑状态——“暂停”只落在任务板上与接管账本里。
- **交还时记什么**：`--did`（接管期间做了什么）、`--resume-from`
  （Bot 从哪一步继续）。两者先过确定性打码（与看屏同款规则：密码 /
  验证码 / 卡号）再记，原文不留存；打了哪几类在交还输出里明说。

**审计字段**：一次接管就是接管账本（`~/.nyra/takeovers.json`，原子写
0600，损坏先备份再抛错）里的一行——谁、何时、为什么、暂停了哪几个任务、
交还时做了什么、Bot 从哪步继续、恢复了哪几个任务；同时记一笔电脑活动账本
（`screen.takeover` / `screen.handover`），有 `--run` 且运行真实存在时
再镜像两条运行事件（`bot_takeover_started` /
`bot_takeover_ended`，已注册进 `EVENT_FIELDS`，时间线有渲染）。
审计里不记密码/验证码/支付信息原文。

## 诚实边界

- **本机没有真实浏览器画面**：看屏与接管都是假画面/回环模型——“画面描述”是活动
  摘要的确定性文本，不是模型看图的结果；假帧没有像素，不调模型。
- 真实浏览器画面的抓取与传输未接通（本机只在假画面/回环上验过）。
- **接管动作也是确定性模型**：接管只记“我接管了、Bot 停了、我做了什么、
  交还了”，不抓真实浏览器画面、不注入真实输入；真实浏览器画面的抓取与
  输入注入未接通。
- 看屏期间 Bot 不暂停（因为人没有在操作同一台电脑，无双写可防）；接管
  期间 Bot 才暂停。
- 真 API 未跑通，只在假 provider 与本地确定性检查上验过；
  Windows/macOS 真机未验证。
