# 免疫体检（H4）

大脑自己的逐项自检：记忆条目证据还在不在、技能文件还能不能解析、配置有没有坏、密钥有没有进明文、账本有没有损坏。不合格的**隔离，不删除**，并上报。

入口只有一个：

```text
nyra doctor --deep
```

`nyra doctor` 不加 `--deep` 时不跑免疫体检（保持原来自检的速度与输出）。

## 检查项（7 项，对齐三件护城河）

| 检查 | 护城河 | 查什么 | 不合格怎么办 |
|---|---|---|---|
| 记忆证据 | 证据链 | 每条记忆的证据引用是不是 1–8 条非空 | 条目隔离：隔离区留快照 + 账本里标 `deleted`（修订历史保留） |
| 技能文件 | 证据链 | `~/.nyra/skills/` 里的 `.md` 能不能解析 | 文件移进隔离区 |
| 配置有效 | 权限边界 | `config.json` 能不能解析，`dream` / `mcp_server` 两节形状对不对 | 损坏的 `config.json` 移进隔离区（下次运行重建默认配置） |
| 密钥明文 | 权限边界 | 配置与账本里有没有明文密钥（只报种类名与文件，绝不回显密钥原文） | 记忆条目里的隔离；配置/账本里的只报，请你亲手处理 |
| 账本完好 | 证据链 | 14 个账本逐个解析（JSON / JSONL） | 坏的移进隔离区 |
| 成本硬顶 | 成本硬顶 | 上限配置是不是非负数字、暂停账本能不能解析 | 只报，不自动改 |
| 权限位 | 权限边界 | 配置目录 700、密码箱与账本 600 | 只报，不自动改权限 |

说明：

- **月度上限已移除**：首次付费调用前不再有“先选上限”的门（P0-3 的运行时门已拆掉）；体检不再检查这一项。
- **配置损坏的判定**：`loadConfig` 损坏时不抛错、直接回默认值，所以体检自己读 `config.json` 原文 JSON 来验。
- **权限位检查在 Windows 上跳过**（没有 POSIX 位），报“不检查”而不是失败。
- **证据目录不扫**：`evidence/` 是审计链，动它会断链；密钥明文只扫配置与账本。

## 隔离区

`~/.nyra/quarantine/`（0700）。文件移进去改名留底（如 `config.json.corrupt-20261125-070000`）；记忆条目在隔离区留一份快照 JSON，账本里标 `deleted`。恢复办法：文件直接移回来；记忆条目在账本修订历史里还有，误删了找我恢复。体检**不删除任何东西**。

## 落盘与证据

- `immune-report.json`（0600）：最新一次体检的完整报告（检查项、是否通过、隔离清单）。
- 证据链：`evidence/immune/` 里每轮一条 `immune_check` 事件（只记计数）与每条隔离一条 `immune_quarantined` 事件（只记隔离区相对名与原因）；运行事件类型已注册进 `src/runs.ts` 的 `EVENT_FIELDS`。
- `--deep` 的输出：免疫体检的 7 项追加进 `nyra doctor` 的检查列表（`免疫体检：记忆证据`……），有一项不过整体就不通过（exit 1）。

## 一处记忆门语义的窄改动

`src/memoryGate.ts` 的 `updateMemoryEntry` 以前任何改动都要附新依据——即使只是标 `deleted`。这会让证据本身已坏（如引用为空）的条目死锁在“删不掉”。本批改成：**只删不改**（patch 里只有 `status: "deleted"`）时不需要新依据，沿用原条目依据；秘密拦截也跳过（删除不写新断言，旧内容已在账本里，拦删除只会让含密钥的条目删不掉）。改正文、改主题、改出处时，证据门与秘密拦截原样不变。
