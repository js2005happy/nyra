简短版本：Nyra 不收集你的数据。它运行在你的电脑上，数据存在你的电脑上；你选择使用的模型服务商会收到你发给它的内容。本网站不使用 Cookie，也不做统计分析。下面是完整说明。The short version: Nyra does not collect your data. It runs on your computer and keeps its data there; the model provider you choose receives what you send it. This website uses no cookies and no analytics. The details follow.

1. 这份政策覆盖什么What this policy covers

本政策说明 Nyra 开源软件和本网站如何处理信息。「我们」指 Nyra 开源项目维护者。我们不运营任何接收用户数据的服务器，也不提供账户。

This policy explains how the Nyra open-source software and this website handle information. “We” means the Nyra open-source project maintainers. We run no server that receives user data, and we offer no accounts.

2. 本网站This website

  • 本网站是托管在 GitHub Pages 上的静态页面，不使用 Cookie，不使用任何统计、分析或广告工具，也不从其他域名加载字体、脚本或图片；
  • 唯一在你浏览器里保存的信息，是你选择的显示语言，存于 localStorage 的 nyra-lang 键中，只留在你的设备上，你可以随时在浏览器设置里清除；
  • 作为托管方，GitHub 可能出于安全和运维需要处理访问日志等技术信息（例如 IP 地址），适用 GitHub 隐私声明。
  • This website is a set of static pages hosted on GitHub Pages. It uses no cookies, no statistics, analytics or advertising tools, and loads no fonts, scripts or images from other domains;
  • The only thing stored in your browser is your chosen display language, kept under the nyra-lang key in localStorage. It stays on your device and you can clear it in your browser settings at any time;
  • As the host, GitHub may process technical information such as access logs (for example IP addresses) for security and operations, under the GitHub Privacy Statement.

3. Nyra 软件不发送遥测The Nyra software sends no telemetry

Nyra 不包含遥测、使用统计、崩溃上报或「回传」功能，不会向项目维护者发送任何数据，也不需要注册账户。Nyra 只会在完成你交给它的任务时，联系你配置的服务（见第 6 节）。

Nyra contains no telemetry, usage statistics, crash reporting or “phone home” feature. It sends nothing to the maintainers and needs no account. Nyra contacts outside services only to do the work you give it, and only the ones you configure (see section 6).

4. 保存在你电脑上的数据Data stored on your computer

Nyra 把运行数据保存在你电脑上的 ~/.nyra 目录中，包括：

  • config.json：你的配置（Nyra 不会把 API Key 写进去）；vault.json、keys.json：你保存的 Key（见第 5 节）；devices.json：已配对手机的记录（只存访问凭证的哈希）；
  • sessions/：会话记录；
  • MEMORY.md、AGENTS.md：记忆与全局说明；
  • evidence/：联网时保存的网页原文（证据）；
  • checkpoints/：用于 /undo、/rewind 的文件快照；
  • schedule.json：定时任务；以及 skills/、commands/、groups/ 等目录。

此外，计划模式生成的 plan.md、你批准写入的文件，以及项目级 .nyra/commands/ 位于你的工作目录中。这些数据不会离开你的电脑，除非你把它们放进发送给模型的上下文、或自行复制分享。删除 ~/.nyra 目录即可清除全部本地数据。

Nyra keeps its working data in the ~/.nyra directory on your computer, including:

  • config.json: your settings (Nyra never writes API keys into it); vault.json and keys.json: keys you saved (see section 5); devices.json: paired phones (only a hash of each access token);
  • sessions/: session history;
  • MEMORY.md and AGENTS.md: memory and global instructions;
  • evidence/: original web pages saved as evidence;
  • checkpoints/: file snapshots for /undo and /rewind;
  • schedule.json: scheduled tasks; plus folders such as skills/, commands/ and groups/.

Plans from plan mode (plan.md), files you approve writing, and project-level .nyra/commands/ live in your working directory. None of this leaves your computer unless it is placed in context sent to a model, or you copy and share it yourself. Deleting ~/.nyra removes all local data.

5. API KeyAPI keys

  • 环境变量里的 Key（例如 DEEPSEEK_API_KEY）永远优先；
  • 你在 Nyra 界面里填写的 Key，在本机加密密码箱已解锁时存进密码箱（~/.nyra/vault.json，主密码经 PBKDF2-HMAC-SHA256 派生），否则写进 ~/.nyra/keys.json（macOS 和 Linux 上权限 0600）；Nyra 不会把 Key 写进 config.json、会话记录或日志；
  • 界面和接口只显示 Key 的掩码（例如 sk-…abcd），不会把明文回传给页面；
  • 模型服务返回的错误信息在显示前会去掉 Key；
  • Key 只发送给它所属的模型服务商，用于请求认证；
  • MCP 服务器子进程默认拿不到你的 API Key。
  • A key in an environment variable (for example DEEPSEEK_API_KEY) always takes priority;
  • A key you enter in the Nyra app is stored in the encrypted local vault when it is unlocked (~/.nyra/vault.json, with the master password derived through PBKDF2-HMAC-SHA256), otherwise in ~/.nyra/keys.json (mode 0600 on macOS and Linux). Nyra never writes keys into config.json, session history or logs;
  • The app and its API only show a masked key (such as sk-…abcd) and never send the plain key back to the page;
  • Error messages from model services are redacted to remove keys before display;
  • A key is sent only to the model provider it belongs to, to authenticate requests;
  • MCP server subprocesses do not receive your API keys by default.

6. 会发送给第三方的内容What is sent to third parties

为完成你交给它的任务，Nyra 会联系以下服务。它们各自适用自己的隐私政策：

  • 你配置的模型服务商：收到你的指令，以及完成任务时放进上下文的文件内容、命令输出和工具结果。请在选用前阅读该服务商的隐私政策与数据使用条款。使用本地 Ollama 时，这些内容留在你的电脑上；使用 Codex CLI 时，内容经由你本机的 Codex CLI 与你的账号发送；
  • 搜索引擎与网站：web_search 会把搜索词发送给公共搜索引擎（目前为 Bing 和百度），web_fetch 会访问你或 agent 打开的网址，这些网站会看到常规的网络请求信息，例如你的 IP 地址；
  • 你批准的网络请求：例如 http_post 或 shell 命令发出的请求，发往你批准的目标；
  • 你接入的聊天渠道与连接器：例如 Telegram、Discord、Slack、WhatsApp、Gmail、Shopify，会收到 Nyra 为完成任务发出或读取的消息与数据；
  • MCP 服务器：你配置的服务器会收到 agent 调用它时传递的参数。

本地网页界面默认只监听 127.0.0.1，每次启动生成随机访问 token，不对外提供服务。只有你运行 nyra ui --pair 或指定 --host 时，它才会在局域网上监听，供你配对的手机连接；手机与电脑之间直接通信，不经过项目维护者的服务器。

To do the work you give it, Nyra contacts the services below, each under its own privacy policy:

  • The model provider you configure receives your instructions plus the file contents, command output and tool results placed in context for the task. Read that provider’s privacy policy and data-use terms before choosing it. With a local Ollama model, this stays on your computer; with the Codex CLI, it is sent through your local Codex CLI under your account;
  • Search engines and websites: web_search sends the query to public search engines (currently Bing and Baidu), and web_fetch visits the URLs you or the agent open. These sites see ordinary request information such as your IP address;
  • Network requests you approve, such as those made by http_post or shell commands, go to the destinations you approved;
  • Chat channels and connectors you set up, such as Telegram, Discord, Slack, WhatsApp, Gmail and Shopify, receive the messages and data Nyra sends or reads for your task;
  • MCP servers you configure receive the arguments the agent passes when calling them.

The local web UI listens only on 127.0.0.1 by default, creates a random access token on each launch, and serves no one else. Only when you run nyra ui --pair or set --host does it listen on your local network so your paired phone can connect; the phone talks to your computer directly, not through any server run by the maintainers.

7. 你的选择Your choices

  • 使用 readonly 模式，让 Nyra 只读不写；
  • 使用本地模型（如 Ollama），让上下文不离开你的电脑；
  • 不要把密码、密钥或他人的个人信息放进会话；
  • 随时删除 ~/.nyra 中的会话、证据和记忆。
  • Use readonly mode so Nyra reads but never writes;
  • Use a local model (such as Ollama) so context never leaves your computer;
  • Keep passwords, secrets and other people’s personal data out of sessions;
  • Delete sessions, evidence and memory in ~/.nyra at any time.

8. 儿童Children

Nyra 是面向开发者和专业用户的工具，并非为儿童设计。我们不会有意收集任何人的个人信息，包括儿童的个人信息。

Nyra is a tool for developers and professionals and is not designed for children. We do not knowingly collect personal information from anyone, including children.

9. 政策变更Changes to this policy

如果 Nyra 处理信息的方式发生变化，我们会更新本页面并修改生效日期，重要变更会写进仓库的更新日志。

If the way Nyra handles information changes, we will update this page and its effective date, and record significant changes in the repository history.

10. 联系我们Contact

隐私方面的问题，请在 GitHub Issues 提出。请不要在公开 Issue 中贴出个人信息或 API Key。

Raise privacy questions on GitHub Issues. Please do not post personal information or API keys in a public issue.
