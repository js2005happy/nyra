# Nyra 下一步路线：从"能用"到"最强"

> 写于 2026-11-19。基于此前内部竞品调研的差距矩阵（调研原文已从公开站点下线，见 git 历史），回答一个问题：**凭什么说 Nyra 比别家好？**

---

## 一、先承认一件事

"比市面上所有 agent 都好"是个没有终点、也无法验证的目标。任何宣称"全面最强"的路线图都会变成功能清单竞赛——而功能清单是比不完的（Claude Code 有 28 个 hook 事件，明天可能 40 个）。

**可防守的目标只有一个：在某个窄面上做到别人做不到，其余面做到平齐。**

---

## 二、Nyra 的窄面候选（三选一）

| 候选 | 别家现状 | Nyra 现有基础 | 判断 |
|---|---|---|---|
| **A. 长任务可信度**：任务结束能自证、失败不静默 | 都在做，但没人把"证据"做成一等公民；Codex/CC 靠人肉看 diff | `evidence.ts` `artifacts.ts` `runs.ts` `--verify` | ✅ **最强候选**。已有骨架，缺"强制验收" |
| **B. 成本可预测**：硬顶 + 实时看板，超支即停 | 全部缺失。CC 只报 token，Codex 不报钱 | `usage.ts` `mcpCost.ts` `max_turns` | ✅ 次强候选。几乎无人竞争 |
| **C. 本地权限边界**：跨平台 OS 沙箱 + 可审计规则 | CC 有 Seatbelt/bwrap，Codex 有 workspace-write，都只覆盖部分平台 | `sandbox.ts`（仅 Linux bwrap） | ⚠️ 追平项，不是差异项 |

**结论：主打 A + B，C 作为追平项补齐。** 一句话定位：

> **Nyra = 唯一一个"跑完能自证、成本有硬顶、权限有边界"的本地 agent。**

这不是营销口号，是可以写进验收标准的工程约束。

## 三、P0：先追平（把"不如人"的地方补掉）

| # | 能力 | 别家基线 | Nyra 现状 | 验收标准 |
|---|---|---|---|---|
| P0-1 | 受保护写入路径 | Codex 对 `.git/.agents/.codex` 只读 | ✅ PR #31 | 顶层规则文件/`.git` 拒写，sshell 除外需文档写明 |
| P0-2 | 子 Agent 隔离 | CC `isolation: worktree` + 工具白名单 + 独立模型 | ✅ PR #33 | 子任务改动不进主工作区；只读子任务拿不到 shell |
| P0-3 | 技能 frontmatter + 动态注入 | CC `allowed-tools` / `model` / `!`cmd`` | ✅ PR #32（含信任模型） | 项目技能不自动执行命令 |
| P0-4 | hooks 可改参数 | CC `PreToolUse` 返回 `updatedInput` | ❌ 只能 allow/deny | 能"改写参数后放行"，且有测试 |
| P0-5 | 权限规则语言 | CC `Tool(specifier)`，deny>ask>allow | ❌ 只有工具粒度交互式审批 | `Bash(git *)` / `Edit(src/**)` 可写进配置并生效 |
| P0-6 | macOS/Windows OS 沙箱 | CC Seatbelt / Codex 平台隔离 | ❌ 只有 Linux bwrap | macOS 用 `sandbox-exec`，Windows 用 Job Object/AppContainer |

**P0 全部完成 = 平齐。** 预计 3 个 PR（P0-4+5 合并做一个策略层，P0-6 单做一个）。

## 四、P1：做出差异（A：长任务可信度）

| # | 能力 | 为什么别人做不到 | 验收标准 |
|---|---|---|---|
| P1-1 | **完成即自证**：任何 `--verify` 未通过的运行，不得输出"已完成" | 别家把"完成"交给模型自己宣布 | 无证据的完成声明直接降级为"未验证"，并给出复跑命令 |
| P1-2 | **证据链落盘**：工具调用 → 产物 → 校验结果三元组可回放 | CC/Codex 只有 transcript，没有可校验产物 | `nyra evidence verify <run-id>` 能独立复核并通过/失败 |
| P1-3 | **失败不静默**：三类失败必须显式区分（工具错/模型错/验证错） | 别家统一报"出错了" | 退出码 + JSON 事件里三分类，且 `--json` 有稳定 schema |
| P1-4 | **断点续跑不重复副作用** | 已实现一半（runs/checkpoints） | 中断后 `--resume-run` 不重复已成功的写操作（幂等键） |

## 五、P2：做出差异（B：成本可预测）

| # | 能力 | 验收标准 |
|---|---|---|
| P2-1 | 用户配置单价表，运行前给预算估值 | `nyra cost --estimate "<task>"` 输出区间，误差可解释 |
| P2-2 | **硬顶**：超预算即停，不是警告 | 达到 `--max-cost` 立即中止并落盘原因，退出码专用 |
| P2-3 | 实时看板（TUI + `--json` 事件） | 每轮更新已花费/剩余，未报告 usage 时显示"未知"而非瞎猜 |

## 六、P3：生态（追平即可，不投入差异化）

插件市场与治理、MCP 工具延迟加载、IDE 集成、更多网关。这些是"有没有"的问题，不是"强不强"的问题。

---

## 七、判断标准（怎么知道我们在变强）

不设"功能数量"，只设**可复现的行为断言**，全部进 CI：

1. **不可自证 = 失败**：任何"已完成"输出若无验证证据，测试直接红。
2. **超预算 = 中止**：给定 `--max-cost`，模拟超支必须中止且退出码正确。
3. **隔离 = 字节级**：子 Agent 在 worktree 里改文件，主工作区哈希不变。
4. **权限 = 可预测**：给定规则集，一批命令/路径的放行结果必须与声明一致（表驱动测试）。
5. **不静默**：任何 catch 分支都要么降级为显式说明，要么向上抛，禁止 `catch {}` 吞掉。

> 第 5 条建议直接做成 lint/测试：`src/` 里出现空 catch 即失败。这是我们相对别家的工程纪律优势，也最容易腐化。

## 八、执行顺序（接下来 6 个 PR）

```
① P0-4 + P0-5  hooks updatedInput + 权限规则语言（策略层，1 个 PR）
② P0-6         macOS Seatbelt 沙箱
③ P1-1         完成即自证（--verify 强制门）
④ P2-2         成本硬顶
⑤ P1-3         失败三分类 + 稳定 JSON schema
⑥ P2-1         成本预估
```

每个 PR 都带表驱动测试；跑不动 bun 的机器用 Node type-stripping 兜底验证（本机现状）。

---

## 九、不做什么（避免变成功能清单竞赛）

- 不追 hook 事件数量。事件按需加，一处一测。
- 不做自己的模型。模型是别人的战场。
- 不和 Cursor/Devin 抢 IDE 与托管。Nyra 的战场是**本地 + 可审计**。
- 不为了"看起来强"加功能：任何新能力必须能写进上面第七条的可复现断言。

## 十、怎么自检（不用记清单）

上面第七条的可复现断言，已经有一部分变成命令：

```bash
nyra redlines        # 上线红线自检：成本上限 / 定价 / OS 沙箱 / deny 规则 / 验证命令 / 钩子
nyra doctor          # 能不能跑起来：运行时 / Key / 网络 / 磁盘 / 权限
nyra evidence verify <run-id>   # 这次运行的证据链是否成立（重算产物哈希 + 调用闭合）
nyra cost --estimate "<task>"   # 跑之前先知道大概多少钱
```

`nyra redlines` 的三层判定：

| 级别 | 含义 | 例子 |
|---|---|---|
| ✅ ok | 已设好 | 配了 `max_cost_usd` 与 `pricing` |
| ⚠️ warn | 缺省可接受，但长任务前该补 | 没配 deny 规则、没有验证命令 |
| ❌ fail | 明确危险，不宜上生产 | `sandbox_mode: danger-full-access`、`permissions.allow` 里有裸 `Bash` |

退出码 0 = 没有 fail；1 = 有 fail。CI 里可以直接当门。
