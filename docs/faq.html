入门Getting started

Nyra 是什么？What is Nyra?

Nyra 是跑在你自己电脑上的开源 AI agent。它能读懂项目、改代码、跑命令、上网查资料并附上出处；写文件和执行命令之前，默认都会先问你。Nyra is an open-source AI agent that runs on your own computer. It reads your project, edits code, runs commands and researches the web with sources, and by default it asks before it writes a file or runs a command.

运行它需要什么？What do I need to run it?

一台 macOS（Apple 芯片或 Intel）、Windows（x64）或 Linux（x64 / arm64，需要 glibc）电脑，再加一个模型服务商的 Key，或者本机的 Ollama。Nyra 是单文件程序，不用另外装 Python、Node 或 Bun。A Mac (Apple silicon or Intel), a Windows PC (x64) or a Linux machine (x64 / arm64 with glibc), plus a key from a model provider or a local Ollama. Nyra is a single self-contained program; you don't need Python, Node or Bun.

怎么安装？How do I install it?

到本页的下载区下载你平台的桌面安装包，装好后跟着首次设置向导选模型、填 Key、测试连接。只要命令行版的话，下载对应的文件后运行 nyra setup。Grab the desktop installer for your platform from the download section, then follow the setup wizard to pick a model, add a key and test the connection. For the command line only, download the matching file and run nyra setup.

Nyra 收费吗？Does Nyra cost anything?

Nyra 本身免费、开源，以 MIT 许可发布。调用模型的费用在你和模型服务商之间结算；也可以用本机的 Ollama，或复用本机的 Codex 登录。Nyra itself is free and open source under the MIT License. Model usage is billed between you and your provider; you can also use a local Ollama model or reuse the Codex sign-in on your machine.

还没有 Key，能先试试吗？Can I try it without a key?

可以先运行 nyra --help、--version 和 --list-providers，它们不联网、不花钱。没设 Key 就跑模型任务时，Nyra 会打印设置说明后退出，不会发出任何请求。也可以直接用本机的 Ollama。You can run nyra --help, --version and --list-providers; they don't touch the network or cost anything. Start a model task without a key and Nyra prints setup instructions and exits without sending a request. You can also use a local Ollama model.

模型Models

支持哪些模型？Which models does it support?

DeepSeek（默认）、xAI Grok、OpenAI、通义千问、Kimi、智谱 GLM、Gemini、OpenRouter、Mistral、Groq、Together、本机 Ollama、本机 Codex 登录，以及任何兼容 OpenAI 接口的自定义服务。运行 nyra --list-providers 查看全部。DeepSeek (the default), xAI Grok, OpenAI, Qwen, Kimi, Zhipu GLM, Gemini, OpenRouter, Mistral, Groq, Together, a local Ollama, the Codex sign-in on your machine, and any custom OpenAI-compatible endpoint. Run nyra --list-providers to see them all.

主模型出错时会自动换模型吗？Does it switch models if the main one fails?

默认不会。备用模型默认关闭，你开启后才生效，而且只会换到你列出的模型；真的换了，会立刻告诉你。Not by default. The fallback is off until you turn it on, it only switches to models you listed, and when it does switch it tells you right away.

安全与审批Safety and approvals

它会不会乱改我的文件？Will it mess with my files?

默认的「写入前先问」模式下，写文件和跑命令前都会先问你。文件工具写不出当前工作目录，.git、.nyra 和 AGENTS.md 这类路径默认拒写。每次写入前都会存检查点，改错了可以 /undo。In the default Ask before writing mode, it asks before it writes a file or runs a command. File tools can't write outside your working folder, and paths like .git, .nyra and AGENTS.md are protected by default. A checkpoint is saved before every write, so /undo can take it back.

有哪几种审批模式？What approval modes are there?

只读（readonly）：读文件、上网查资料，不写也不执行。写入前先问（auto，默认）：写文件或执行命令前逐项问你。完全访问（full）：这一轮不再确认，只用在你明确信任的任务上。可以在输入框下方、会话里的 /mode 或启动参数 --mode 切换。Read-only (readonly) reads files and searches the web but never writes or runs anything. Ask before writing (auto, the default) asks before each write or command. Full access (full) stops asking for the run; use it only for tasks you trust. Switch from the pill under the input, with /mode, or with --mode.

「始终允许」会不会放得太宽？Is “Always allow” too broad?

不会。「始终允许」按命令前缀记成规则，可以只管本次会话，也可以管整个项目，随时在 设置 → 权限与审批 里撤销。删除、提权、联网和复合命令（带 ;、&&、| 之类）只能单次允许，规则绕不过去。No. “Always allow” saves a command-prefix rule for this session or the whole project, and you can revoke it any time under Settings → Permissions & approvals. Deletes, privilege escalation, network access and compound commands (with ;, &&, | and so on) can only be allowed once; rules can't be used to sneak them through.

改错了怎么办？What if it gets something wrong?

/undo 撤销上一步，/rewind 3 回到三步之前。检查点只管本地文件，撤销不了 shell 命令、网络请求这类外部影响。/undo reverts the last step and /rewind 3 goes back three. Checkpoints cover your local files; they can't undo side effects such as shell commands or network requests.

能先看计划再执行吗？Can I review a plan before it runs?

可以。nyra --plan 会只读地写出 plan.md，你审过之后按它的 SHA-256 批准执行；计划改动一个字节，旧的批准就失效。Yes. nyra --plan writes plan.md without changing anything; once you've reviewed it, approve that exact version by its SHA-256. Change a single byte and the old approval no longer counts.

Nyra 是沙箱吗？Is Nyra a sandbox?

Nyra 可以把命令放进系统沙箱：Linux 用 bwrap，macOS 用 seatbelt，Windows 用 Job Object（--sandbox 指定）。默认的 auto 在 Linux 上有 bwrap 就用，条件不满足时会明说，不会悄悄裸跑。处理来路不明的代码时，仍然建议用虚拟机或容器。Nyra can run commands in an OS sandbox: bwrap on Linux, seatbelt on macOS, Job Object on Windows (choose with --sandbox). The default, auto, uses bwrap on Linux when it's available and tells you plainly when a sandbox isn't, rather than quietly running without one. For untrusted code, a virtual machine or container is still the safer choice.

我的 Key 存在哪里？Where are my keys stored?

环境变量里的 Key 永远优先。在 Nyra 里填的 Key，密码箱已解锁时存进本机加密密码箱，否则写进 ~/.nyra/keys.json（macOS 和 Linux 上权限 0600）。界面和接口只显示掩码，比如 sk-…abcd，明文不会回传。A key in an environment variable always wins. A key you enter in Nyra goes into the encrypted local vault when it's unlocked, otherwise into ~/.nyra/keys.json (mode 0600 on macOS and Linux). The app and its API only show a mask like sk-…abcd; the plain key is never sent back.

我的数据存在哪里，会发给谁？Where does my data live, and who sees it?

会话、记忆、证据、检查点、定时任务和设置都在你电脑的 ~/.nyra 里，Nyra 不发遥测。完成任务时，你的指令和放进上下文的内容会发给你选的模型服务商；用本机 Ollama 时这些内容不出电脑。详见隐私政策。Conversations, memory, evidence, checkpoints, schedules and settings live in ~/.nyra on your computer, and Nyra sends no telemetry. To do a task, your instructions and the content placed in context go to the model provider you chose; with a local Ollama model they never leave your machine. See the Privacy Policy.

手机与自动化Phone and automation

手机端要从应用商店装吗？Do I need an app from the store?

不用。在电脑上运行 nyra ui --pair，用手机扫终端里的二维码（或打开它给出的地址、输入配对码），再添加到主屏幕。安卓也可以装 Release 里的 APK（调试版）。手机和电脑需要在同一个 Wi‑Fi 下，工具始终在电脑上执行。No. Run nyra ui --pair on your computer, scan the QR code in the terminal with your phone (or open the address it prints and enter the code), then add it to your home screen. On Android you can also install the APK (debug build) from the release. Your phone and computer need to be on the same Wi‑Fi, and tools always run on the computer.

能让它定时干活吗？Can it run tasks on a schedule?

可以。nyra schedule add 按间隔或每天定时跑任务，到点后进入任务队列。遇到需要审批的操作会停下来等你，定时任务也不能用完全访问。Yes. nyra schedule add runs a task on an interval or daily, and each run joins the task queue. Anything that needs approval stops and waits for you, and scheduled tasks can't use full access.

其他Everything else

为什么系统提示安装包不安全？Why does my system warn me about the installer?

Windows 和 macOS 的安装包还没有签名和公证。Windows 上点「更多信息 → 仍要运行」；macOS 上到 系统设置 → 隐私与安全性 点「仍要打开」，放行一次即可。签名正在准备。The Windows and macOS installers aren't signed or notarized yet. On Windows choose More info → Run anyway; on macOS go to System Settings → Privacy & Security and click Open Anyway, once. Signing is in the works.

怎么卸载？How do I uninstall it?

用安装脚本装的，加 --uninstall 再跑一次（Windows 是 -Uninstall）；用安装包装的，按系统的常规方式卸载；手动下载的命令行文件，直接删掉即可。你的数据目录 ~/.nyra 会保留，需要的话自己删除。If you used an install script, run it again with --uninstall (-Uninstall on Windows). If you used an installer, remove it the usual way for your system. If you downloaded the command-line file, just delete it. Your data folder ~/.nyra is kept; delete it yourself if you want.

用的是什么许可证？What license is it under?

MIT 许可证。你可以自由使用、修改和分发，包括商业用途，只需保留版权和许可声明。软件按「原样」提供，不附带任何担保。全文见 LICENSE。The MIT License. You may use, modify and distribute it freely, including commercially, as long as you keep the copyright and license notice. The software is provided “as is”, without warranty. See LICENSE.

遇到问题去哪里反馈？Where do I report a problem?

到 GitHub Issues 提问题，最好附上报错原文和 nyra doctor 的输出。也欢迎直接提 Pull Request。Open an issue on GitHub Issues, ideally with the exact error and the output of nyra doctor. Pull requests are welcome too.
