# 手机上用 Nyra（PWA + 扫码配对）

Nyra 的手机版是电脑上 `nyra ui` 顺带提供的一个手机页面
（`/m`），可以像 App 一样装到主屏幕：安卓用 Chrome，iPhone 用 Safari。
不用应用商店，没有 APK / IPA，也不经过任何外部服务——手机直接连你
电脑上跑着的 Nyra，Nyra 的工具仍在电脑上执行。

> **新入口（第 6 批）：** 手机 App 现在主推账号登录 + 直连云端
> （`nyra cloud`，详见 `docs/mobile-cloud.md`），不再要求手机与电脑
> 在同一个 Wi-Fi 里。本文件讲的仍是旧版局域网路子（扫码配对连 `/m`）：
> 云端没上线前它仍是唯一能走通的手机路，保留；云端上线走通后，
> 旧版入口再删。

手机上能做的：看会话列表、进会话看对话流、发新任务、在审批卡上
**允许一次 / 本会话始终允许 / 拒绝**（大按钮，diff 可左右滑动），以及在
**审阅**标签页里逐项批并行线程与定时任务的结果（diff 统计 + 验证结论 +
成本，见 docs/review-queue.md）。底部
五个标签：**对话 / 审阅 / 自动化 / 技能 / 设置**。有待
审批时，页面标题变成 `(1) Nyra`，支持的系统上主屏幕图标也会出现角标
（Badging API，纯本地，不是推送通知；App 在后台被系统挂起时不会提醒）。

> **如实说明：没有在真手机上验证过。** 这套流程只在电脑上用 Playwright
> 模拟 iPhone 14 与 Pixel 7（Chromium 内核、模拟 standalone 显示模式）
> 实际跑过：扫桌面二维码（截图后用解码器读出链接）→ 配对 → 以“已安装
> App”方式启动、入场动画播放并结束 → 在手机页面上批准一次
> 审批。真机上的“添加到主屏幕”菜单、系统启动屏、iOS 独立窗口的存储
> 行为都还没亲手试过，第一次在真机上装时如有出入，以手机上实际出现的
> 为准，并欢迎反馈。

> Node 版（2026-11-19）：手机页已移植到 Node/TypeScript 的 gateway（`nyra ui`），
> 见文末“Node 版实现”。在电脑上用 Playwright 模拟 Pixel 7 跑过：配对 → 审批
> （允许并不再询问）→ 拒绝并反馈，以及入场动画与手机设置页；真机验证仍是待办。

## 第 1 步：在电脑上开启配对

```bash
nyra ui --pair
```

`--pair` 会让网页界面监听局域网（`0.0.0.0`，终端会打印一行风险警告），
然后在终端里用方块字符画出一个二维码，并打印：

```text
用手机相机扫描下面的二维码，连接这台电脑上的 Nyra：
（二维码）
或在手机浏览器打开：http://192.168.1.23:8765/m  并输入配对码 482913
配对码 5 分钟内有效、只能用一次、错 5 次作废；…
```

也可以先正常启动，再在网页界面的 **设置 → 手机** 里点 **连接手机**，
页面上会显示同样的二维码（SVG）和配对码，带倒计时。注意：不带
`--pair`（或 `--host`）启动时网页界面只监听本机，按钮会提示“手机连
不上，请用 `--pair` 重新启动”。

二维码里是 `http://<电脑局域网 IP>:<端口>/m#pair=<6 位配对码>`。配对码
放在 `#` 后面，不会出现在服务器日志或 Referer 里。二维码完全在本机生成
（`src/qrcode.ts`，Node 版 QR 编码器），不调用任何在线服务。

建议固定端口（默认 8765），并在路由器里给电脑设一个固定 IP（DHCP
保留）：手机 App 记住的是“IP + 端口”，换了地址就得重新配对。

## 第 2 步：手机扫码配对

1. 手机和电脑连**同一个 Wi-Fi**。
2. 用手机相机扫码，打开链接。页面会自动用配对码换取这台手机专属的
   长期 token，存进手机浏览器的 localStorage，然后进入会话列表。
3. 扫不了码也行：手机浏览器打开终端里打印的 `http://…/m`，输入 6 位
   配对码。

配对码一次性：一台手机配对成功后这个码就失效；要连第二台手机，在设置
里再点一次“连接手机”生成新码。

## 第 3 步：安装到主屏幕

**安卓（Chrome）：** 在已配对的页面点右上角 ⋮ →**添加到主屏幕**（或
“安装应用”）。

**iPhone（Safari）：** 点底部“分享” →**添加到主屏幕**。

从主屏幕图标打开时，会先看到系统启动屏（深色 `#1a1a1a`），接着是 Nyra
的入场动画“方块头转眼球”（动画约 2.4 秒、终帧停到 2.65 秒再淡出进应用：
方块头从暗处浮现并睁眼 → 往左看、往右看 → 往上转一圈 → 眨一下眼 → 停在正视，
下方浮现 `Nyra` 字标；不能点按跳过；系统开了“减少动态效果”时只淡入终帧）；
然后进入会话列表。动画源在 `docs/design/splash/`（`splash.js` 的 `frame(t)`、`splash.html` 预览）。

### 已知限制与注意

- **iPhone 主屏幕 App 与 Safari 的存储可能是分开的。** 如果从主屏幕
  打开后又看到“连接电脑上的 Nyra”配对页，在电脑设置里点“连接手机”
  生成新码，在这个页面里输入 6 位码即可（这台手机会多一条设备记录，
  旧的那条可以在电脑上撤销）。
- **安卓 Chrome 对 `http://` 局域网地址可能只创建快捷方式。** Chrome
  只把 HTTPS（或 localhost）网站安装成独立窗口的 App；普通 http 局域网
  地址“添加到主屏幕”后可能仍以浏览器标签打开——这时功能都能用，但
  不算独立窗口，**不会播放入场动画**。想要独立窗口，可以在手机 Chrome 的
  `chrome://flags` 里把 `http://<电脑IP>:8765` 加进
  “Insecure origins treated as secure”（只对自己的电脑这么做）。Nyra 没有
  自带 HTTPS 证书。
- **没有离线能力，没有推送通知。** 没有 Service Worker；电脑上的服务停了，
  手机上也打不开。待审批提醒只在 App 打开着时更新（标题 / 角标 / 列表顶部
  横幅），每 4 秒检查一次。
- **入场动画只在手机上以已安装 App（独立窗口）启动时播放**：每次冷启动
  一次（同一次运行里刷新页面不重播），系统开了“减少动态效果”时只淡入
  终帧。桌面浏览器、手机浏览器的普通标签页、项目官网都不播。动画是
  页面内的 CSS/JS 绘制（SVG），不含视频文件，不发任何外部请求。

## 管理已配对的手机

- 电脑上网页界面 **设置 → 手机** 列出所有已配对设备（名称、配对时间、
  最近使用时间），每台都可以 **撤销**，撤销后该手机立即无法再连接
  （手机端会回到配对页）。
- 也可以调 API：`GET /api/devices` 列出、`POST /api/devices/<设备 ID>/revoke` 撤销（只认电脑端启动 token，运行中的网页界面立即生效）。

- 登记表在 `~/.nyra/devices.json`（POSIX 下权限 0600），里面**只有 token
  的 SHA-256 哈希**，没有 token 本身；最多 20 台设备。

## 安全说明（重要）

- 默认 `nyra ui` 仍只绑 `127.0.0.1`，手机连不上。只有带 `--pair`
  或 `--host` 时才监听局域网，并打印警告。
- 配对码：6 位数字，5 分钟有效，一次性，错 5 次作废（之后连正确的码也
  无效，需重新生成）；重新生成会让旧码立即失效。
- 手机拿到的是设备专属 token（32 字节随机数），只在配对那一次返回；之后
  手机在请求头 `X-Nyra-Device` 里带上它。电脑端常量时间比对哈希。
- 手机 token 能用手机页面的全部功能（看会话、发任务、审批），**但不能**
  再去生成配对码、查看或撤销设备——这些只认电脑端每次启动的访问 token。
- `/m` 页面本身和它的图标、启动图不含任何秘密，所以不需要 token；所有
  API 都需要鉴权。CSP 与桌面页面完全相同，没有放宽。
- 传输是明文 HTTP：只在自己信任的家庭 Wi-Fi 里用。**绝不要把端口映射到
  公网**（路由器端口转发、内网穿透等）：拿到手机 token 的人就能通过 Nyra
  读写文件、执行命令（仍需经过审批模式）。手机丢了，第一时间在电脑上撤销。

## Node 版实现（Codex 式审批卡）

- `src/webuiMobile.ts`：手机页（黑白单色设计稿：底部五标签——对话 / 审阅 / 自动化 / 技能 / 设置；审批为底部弹层，审阅标签页接审阅队列）、
  manifest、图标。图标是应用图标（紫色团子方块，几何在 `src/appIcon.ts`）在本机光栅化：
  192/512 `any`（满格圆角图块，四角透明）、192/512 `maskable` 与 `apple-touch-icon` 180（满版不透明纯紫，系统加遮罩；两只眼都在 80% 安全圆内）、
  favicon（`/m/favicon.svg` 圆角图块版、`/m/favicon-32.png`、`/favicon.ico` 含 16/32/48；≤28 px 眼睛放大）。
- `src/qrcode.ts`：QR 编码器，与 Python 版逐模块一致；`nyra ui --pair` 在终端画二维码，
  `POST /api/pair/start` 额外返回 `qr_svg`。
- `src/pairing.ts`：沿用已有 `DeviceRegistry`（6 位码 5 分钟、一次性、错 5 次作废、token 只存 SHA-256、可撤销）。
- `src/approvalRules.ts`：审批卡上的三个动作——
  - **允许**：只这一次。
  - **允许并不再询问**：卡片上写明具体前缀规则（如“以 `git status` 开头的命令”），选 **仅本会话**
    （内存里，会话结束失效）或 **本项目**（存 `~/.nyra/approval_rules.json`，按项目绝对路径分组，
    从不写进项目目录）。危险程序（rm、sudo、curl、bash -c、python -c……）、危险子命令（git push/reset、
    npm install……）和任何含分号、`&`、`|`、`<`、`>`、`$`、反引号、括号、换行等语法的命令不提供规则，只能单次允许。
    匹配时重新做同样的检查，所以 `git status && rm -rf /`、`git status $(…)`、反引号、换行都匹配不上。
  - **拒绝…**：展开文本框，反馈作为工具错误原样带回给 agent（“用户拒绝执行，并给出反馈：…”）。
- 终端审批菜单的“始终允许”与手机共用同一套规则：shell 命令有建议规则时，终端选“始终允许”记一条
  本会话前缀规则；手机记下的本项目规则在终端同样生效。
- API：`GET /api/approvals` 每项带 `command` 与 `suggestion`；`POST /api/approvals/<id>`
  接受 `{approve, scope: "session"|"project"}` 或 `{approve: false, feedback}`；
  `GET /api/rules[?session=<id>]` 列规则，`POST /api/rules/<id>/revoke` 撤销（手机也可撤销，只会收紧）。
- 入场动画：只在手机主屏幕独立窗口（`display-mode: standalone` / iOS `navigator.standalone`）里播，
  一次冷启动只播一次（sessionStorage），动画 0–2.95 秒、终帧停到 3.8 秒再整层淡出进应用，不能点按跳过；“减少动态效果”时只淡入终帧。
- 手机设置页（右上角“设置”）：已允许规则列表与撤销；模式切换，切到全权要两步确认，
  服务端也要求手机请求带 `confirm: "full"`；API Key 只提示在电脑上输入，手机不显示、不接收 Key；
  “断开这台手机”只清本机 token，彻底撤销仍在电脑上做。
- 测试：`tests/node/test-mobile-pwa-v2.test.ts`。
